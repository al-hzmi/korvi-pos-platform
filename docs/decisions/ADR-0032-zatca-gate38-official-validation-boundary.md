# ADR-0032 — ZATCA Gate 38 official validation boundary

- Status: Accepted
- Date: 2026-09-09
- Scope: ZATCA Phase 2 Gate 38 acceptance evidence
- Supersedes: no prior ADR

## Context

The product-readiness scorecard deliberately separates two fiscal capabilities:

- Gate 38: compliant UBL XML projection, required canonicalisation/transforms and invoice hash.
- Gate 39: CSID lifecycle, cryptographic stamp and Phase 2 simplified-invoice QR tags 6-9.

ZATCA's Electronic Invoice XML Implementation Standard defines compliance validation in two stages: UBL syntax/schema validation followed by content validation against the applicable EN 16931 subset and Saudi CIUS/business rules. OASIS UBL XSD validation alone is therefore insufficient evidence for Gate 38.

The ZATCA public Developer Portal validator validates the whole simplified invoice. An intentionally unsigned Gate 38 artifact is consequently expected to remain invalid until Gate 39 seals it with the required cryptographic stamp/certificate material and QR payload. Treating `valid=false` as either a generic Gate 38 failure or a generic PASS would collapse the scorecard boundary and would make the evidence misleading.

Official references used for this decision:

- ZATCA E-Invoice Specifications: https://zatca.gov.sa/en/E-Invoicing/SystemsDevelopers/Pages/E-Invoice-specifications.aspx
- ZATCA Electronic Invoice XML Implementation Standard (19 May 2023): https://www.zatca.gov.sa/ar/E-Invoicing/SystemsDevelopers/Documents/20230519_ZATCA_Electronic_Invoice_XML_Implementation_Standard_%20vF.pdf
- ZATCA Security Requirements: https://zatca.gov.sa/en/E-Invoicing/SystemsDevelopers/Pages/Security-Requirements.aspx
- ZATCA public Developer Portal validator: https://sandbox.zatca.gov.sa/Compliance

## Decision

### 1. Gate 38 remains an unsigned pre-sealing artifact

Gate 38 produces the exact deterministic XML bytes that are hashed before Gate 39 inserts the excluded signature/QR material. Production code must not add a dummy certificate, placeholder signature, fake CSID or synthetic QR merely to satisfy a whole-document validator.

### 2. Gate 38 requires two independent acceptance layers

The deterministic local proof must continue to establish:

1. UBL 2.1 schema validity against the normative OASIS Invoice XSD.
2. Required KSA line VAT facts independently from Korvi's TypeScript renderer.
3. Byte-for-byte Canonical XML 1.1 equivalence.
4. SHA-256/Base64 equality between Korvi WebCrypto and OpenSSL.

A second external acceptance proof must submit the same synthetic XML bytes generated by production code to the live official ZATCA public Developer Portal validator.

### 3. The official validator boundary is exact and fail-closed

For the current unsigned simplified-invoice Gate 38 artifact, the only accepted residual findings are the Gate 39 requirements observed from the official validator:

Errors:

- `SIGNATURE_ERROR/certificate`
- `SIGNATURE_ERROR/NullPointerException`
- `QR_CODE_ERROR/QRCODE_INVALID`

Warnings:

- `BR_KSA_WARNING/BR-KSA-27` — required QR code is absent.
- `BR_KSA_WARNING/BR-KSA-60` — required cryptographic stamp is absent.

The proof is not an allowlist for arbitrary validation failures. It compares the complete error and warning sets exactly. Any added, removed, duplicated or reclassified finding fails the gate and requires review against the then-current official ZATCA rules.

In particular, any UBL/XSD/schema, EN16931, BR/BR-CO, VAT-category or other KSA content finding is a Gate 38 defect and must not be deferred to Gate 39.

### 4. ZATCA endpoint authority is resolved from the live portal

The proof reads `REACT_APP_API_URL` from the official public portal's `env-config.js` and requires the expected ZATCA gateway authority before transmitting anything. The request contract mirrors the official frontend: raw XML Base64 as `text/plain` with the accepted-language header. Only deterministic synthetic Korvi invoice data is sent; no merchant credential, CSID, production invoice or customer data is used.

### 5. External acceptance is not substituted for deterministic CI

The public ZATCA endpoint is an external dependency. Its workflow is a separate acceptance gate rather than a replacement for standard CI. Gate 38 closure requires a successful official-validator run on the exact candidate/operational SHA in addition to normal CI and deterministic local proof.

Transient external unavailability may justify rerunning the same SHA; it does not justify weakening, skipping or fabricating the official validation result.

### 6. Gate 39 must eliminate these residuals for real

Gate 39 must implement the actual CSID-backed cryptographic stamp and Phase 2 QR tags 6-9 in the required issuance order. Its acceptance must not inherit the Gate 38 residual set. Once Gate 39 is implemented, the complete sealed simplified invoice must be validated as such by ZATCA; dummy certificates, placeholder signatures and fabricated QR payloads are forbidden.

## Consequences

- Gate 38 can be assessed independently without pretending an unsigned artifact is a customer-ready Phase 2 invoice.
- Gate 39 remains a hard release blocker even after Gate 38 closes.
- A change in ZATCA validation behavior becomes visible immediately instead of being hidden behind a broad warning filter.
- The boundary preserves the required issuance pipeline: deterministic financial truth -> UBL -> canonicalisation/transforms -> hash -> real cryptographic stamp -> QR -> persistence/issuance.
